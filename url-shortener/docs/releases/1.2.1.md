## Residual risks

- **The custom error valve depends on embedded Tomcat behavior and installation timing, which could be affected by future container or framework upgrades.**: Retain the raw-request regression tests and packaged-jar smoke checks when upgrading dependencies; those checks exercise the real listener and verify the error format and preserved headers.
- **The valve class is also used by the management server's factory, so its pre-controller errors use JSON there as well.**: This behavior was explicitly recorded in the accepted fix decisions and verified with a packaged-jar management 404 check; keep that check to detect unintended changes.
- **The valve has less than complete changed-file coverage (83.3% line coverage and 50.0% branch coverage).**: The focused malformed-target tests exercise the reported failure paths, and packaged-jar checks cover malformed escapes, 405 header preservation, and management-server behavior; expand tests if the valve's guards or error-writing behavior change.

## Rollback plan

If the release causes issues, redeploy the previous known-good 1.2.0 application artifact and restart the service using the normal deployment procedure. No database rollback is required because this release introduces no schema changes or migration. Rolling back will restore the previous error-rendering behavior, including the malformed-path response defect this release fixes.
